# Unzoo One：智能体的电脑（规划与功能设计）

2026-11-12 定稿。起因：用户评价现在的产品“一点也不智能”。新建任务要先填表，跑一次就结束，每一步都要批准，智能体看不到之前做过什么。

## 1. 定位

**Unzoo One 不是另一个聊天客户端，是智能体的电脑。**

- 思考交给智能体：Claude Code、Codex、agy、OpenCode，用用户自己的订阅。
- Unzoo One 提供它们在自家客户端里拿不到的东西：
  - **终端**（unterm 内核）：会话住在后台服务里，窗口关了不断，长时间跑的程序下次接着用；人能在同一个终端里看着、接手。
  - **带真实登录的浏览器**（Unzoo）：真 Chromium、用户的账号，每个智能体有隔离的身份；还能下载媒体、处理验证码、遇到登录交给人。
  - **管得住**：每个动作按网关的风险等级处理，低风险直接做，有风险才问，全部留记录。
- 不绑定模型厂商。
- 终端和浏览器也作为 MCP 提供给别的客户端（Claude 桌面版、Cursor），它们是入口，不是敌人。

### 竞争对手

| 对手 | 区别 |
|---|---|
| Claude Cowork | 只能用 Claude；沙盒虚拟机，没有真实浏览器登录；定时任务要开着 App |
| Codex 桌面版 | 只能用 OpenAI；面向开发者；浏览器不带账号 |
| Manus | 云端、按量计费；我们在本机，用自己的订阅 |
| Comet、Atlas 等智能浏览器 | 只有浏览器 |
| Warp | 只有终端，面向开发者 |
| Linger（SimplexAI，2026-11 开源） | 主打本地大模型；单人也要装服务端（Go + PostgreSQL）；浏览器用 Playwright；第三方应用的钥匙放在 Composio 云端。值得学的已学，见第 18 节 |

### 判断一个功能值不值得做

它是否用到了智能体在自家客户端里拿不到的能力（持久终端、带登录的浏览器、治理）？只是“更好看的聊天窗口”的不做。

| 步 | 内容 | 状态 |

| 2 | 智能体的电脑：对话旁边实时显示它用的终端和浏览器，人可以接手 | 完成（2026-11-12，见 4.2） |

## 3. 第 1 步：对话优先（详细设计）

### 3.1 用户看到的

导航（装好的产品）：**对话**、收件箱、成果、设置。“首页”和“任务”合并成“对话”；演示版不变。

**对话页**：左侧是对话列表，右侧是当前对话。

**左栏：对话列表**
- 顶部“新对话”。
- 每一行：标题、状态（正在做 / 等你确认 / 完成 / 出错 / 定时）、最近时间。
- 正在做的、等你确认的排在前面。

**空状态**
- 中间一个大输入框：“想让智能体做什么？”。
- 下面几条示例，点一下填进输入框。示例都要用到终端或浏览器，例如：
  - “打开我在某网站的后台，导出上个月的订单”
  - “把这个文件夹里的 PDF 汇总成一份表格”
  - “每天早上 9 点看一下这几个竞品网站有什么更新”
- 发送后立刻建对话、开始运行，不填别的。标题取第一句（沿用 `titleFromRequest`）。

**对话视图**
- 按时间排列，每一轮包括：
  1. **你说的话**：右侧气泡。定时触发的轮次显示“定时运行”。
  2. **它做了什么**：可折叠的动作列表，一行一个动作，例如“运行了 `npm test`”“打开了 example.com”“写入 report.md”。
     - 自动放行的标“自动”；你批准的标“你批准了”；被拒的标“已拒绝”。
     - 正在进行的那轮默认展开，结束的默认折叠成“做了 12 个动作”。
  3. **等你确认**：卡片直接嵌在对话里，有三个按钮：允许、总是允许（同一命令）、拒绝。收件箱里同时也有，在任何一处答复都行。
  4. **它的回答**：完整文字（不再只截最后 600 字），支持基本格式（段落、列表、代码）。
  5. **产出的文件**：文件卡片，点开预览，或在文件夹里显示。
- 正在运行时，文字和动作实时出现。
- 出错时显示原因和“重试”。

**底部输入框**
- Enter 发送，Shift+Enter 换行。
- 正在运行时，发送按钮变成“停下”。
- 发送 = 接着这段对话说：智能体带着之前的上下文继续（同一 CLI 会话续接）。

**对话头部**
- 标题：点击可改。
- 工作文件夹：点击打开。
- “重复”菜单：不重复 / 每天 HH:MM / 每周几 HH:MM。定时运行用对话的第一句需求，每次是新会话，结果追加到这段对话里。
- 更多：删除。

**设置 › 智能体 › 自主程度**（新增，三档）：

| 档 | 自动放行 | 仍然问你 |
|---|---|---|
| 谨慎 | 只读（看文件、看网页） | 其余全部 |
| 平衡（默认） | 只读；工作文件夹内改文件；普通命令；在它自己的浏览器身份里点击、输入 | 危险命令（删除、强推、格式化…）；工作文件夹外改文件；对外发送（上传、推送、发请求）；读取账号或密钥；花钱 |
| 放手 | 除下一列外都放行 | 危险命令；读取账号或密钥；花钱 |

不论哪档，人定的常设规则（“总是允许 / 总是拒绝”）优先。

### 3.2 运行时（unterm）改动

**A. 一轮的完整记录**（`console_tasks.rs`）

`agent_turn` 步骤的 detail 新增两项：
- `reply`：智能体本轮完整的回答文字，上限 64 KB，超出时保留开头和结尾。
- `activity`：动作列表，上限 300 条，每条为
  `{tool, label, risk, decided_by: auto|rule|person|null, decision: allow|deny|null, at}`。
  - `label` 由工具名和参数生成：命令取命令行，文件取路径，网页取网址，截断到 160 字。
  - 运行时生成 `label`，控制台不再自己解析参数。

`summary` 保留（列表和通知用）。

**B. 读一段对话**

`GET /api/console/tasks` 里的 runs 不带 `reply`/`activity`（列表要轻）。新增：

`POST /api/console/tasks/thread {task_id}`：这个任务的全部运行（上限 500），旧的在前，每一轮带 `prompt`、`reply`、`activity`、`outputs`、`trigger`、`state`、`session_id`、`waiting`。

**C. 追问续接**

`POST /api/console/tasks/run` 的 RunRequest 新增 `follow_up: bool`。为真时，运行时找这个任务最近一次有 `session_id` 的运行，用 `agent_session.resume` 续接，调用方不必知道会话 id。没有可续的就开新会话，并在 detail 里记 `continued: false`。定时触发不续接。

**D. 按风险自动放行**

- `unterm-gateway` 新增 `command_risk(command) -> Risk`：按命令内容判断。
  - 删除、强推、格式化、关机、提权、管道到 shell 等 → `Destructive`；
  - 推送、上传、发请求、远程登录 → `ExternalSideEffect`；
  - 其余 → `Exec`。
  - 拼接命令取各段里最高的。
- `unterm-services` 新增 `tool_risk.rs`：`classify(tool, input, cwd) -> Risk`。
  - Claude 内置工具：
    - Read/Glob/Grep/LS/TodoWrite/WebSearch/Task → `Read`；
    - Edit/Write/MultiEdit/NotebookEdit → 工作文件夹内是 `LocalMutation`，外面按 `ExternalSideEffect` 一档（平衡档问，放手档放行）；删除文件是 `Destructive`；
    - Bash/PowerShell → `command_risk`；
    - WebFetch → `ExternalSideEffect`。
  - Codex / agy / OpenCode 的同类工具按同样方式归类（shell、apply_patch、read_file、run_command…）。
  - `mcp__unterm__<group>_<name>` → `<group>.<name>` → `risk_of`；`exec.*` 再叠加 `command_risk`。
  - `mcp__unzoo__`：
    - 导航、读取、截图、快照、提取、滚动、等待 → `Read`；
    - 点击、输入、选择、按键、拖拽 → `LocalMutation`（在它自己的隔离身份里）；
    - 下载 → `LocalMutation`；
    - 上传 → `ExternalSideEffect`；
    - cookie、profile 相关 → `CredentialAccess`。
  - 认不出的工具：不自动放行。
- `Autonomy { Cautious, Balanced, Autonomous }`，放行上限：
  - 谨慎：`Read`；
  - 平衡：`< ExternalSideEffect`，与网关“低于对外影响不问”一致；
  - 放手：`< CredentialAccess`。
  - `Destructive`、`CredentialAccess`、`Financial` 永远要人答。
- `agent_session.start` 参数新增 `autonomy`，存进会话；`resume` 沿用原会话的。
  - 在常设规则之后判断：规则没命中时，风险在上限以内就自动允许。
  - `approval.resolved` 写 `decided_by: "autonomy"` 和 `risk`。
  - `approval.requested` 也带上 `risk`，收件箱可显示。
- `RunSettings` 新增 `autonomy`（默认 balanced），`/api/console/run-settings` 读写。

### 3.3 控制台（app/）改动

- `app/conversations.tsx`：对话页（列表、对话视图、输入框、动作列表、审批卡片、文件卡片），只在装好的产品里用。
- `app/lib/conversation.ts`：纯函数，可以单测：
  - thread 原始数据 → 轮次；
  - 实时事件 → 正在进行的轮次（文字、动作、等待中的审批）；
  - 动作分组与折叠文案；
  - 状态排序。
- provider 新增：
  - `runtime.thread(taskId)`；
  - `runtime.run({followUp})`；
  - 设置里的 `autonomy`。
- 实时：正在运行的轮次用 `brain.events(sessionId, cursor)` 每 700 ms 拉一次，结束后改读 thread。
- 审批：卡片用现有 `/api/agent/decide`（带 remember）。
- page.tsx：
  - 装好的产品里导航换成“对话 / 收件箱 / 成果 / 设置”，渲染 `<Conversations>`；
  - 旧的首页卡片和任务页只在演示版里出现；
  - 收件箱、成果从对话里能跳过去，也能跳回对话。
- 设置 › 智能体：自主程度三档。
- 所有新文字走 `t()`，英文优先。

### 3.4 验收

1. 全新环境：输入一句需求，回车，对话立刻出现并开始，文字实时流出，动作列表实时增长。
2. 平衡档：读文件、在工作文件夹写文件、`npm test` 之类不问；`git push`、`rm -rf`、上传文件会问，审批卡片出现在对话里，批准后继续。
3. 追问“把刚才的结果改成英文”：智能体记得上文，直接改。
4. 关掉窗口再打开：对话完整，包括完整回答和动作列表。
5. 设成每天 09:00：到点运行，结果追加到同一对话。
6. 英文界面没有中文残留；测试全部通过。

### 3.5 实测（2026-11-12，隔离的后台服务 + 真的 Claude Code 2.1.319，受管、平衡档）

- 新对话：一句需求，回车即开始。
  - 写文件（`local_mutation`）、开终端（`exec`）、`dir`（`exec`）都自动放行。
  - `Remove-Item`（`destructive`）在对话里弹出审批卡片，点“允许”后继续，回答实时出现。
- 追问：“不用工具，刚才的文件叫什么、多大？”，答“notes.txt，5 bytes”，`continued=true`。
- 重启后台服务后，对话完整：两轮的话、动作列表和回答都在。
- 浏览器任务：`browser_navigate`（`exec`）和读页面（`read`）都自动放行。
- 实测发现并修复：智能体挂 Unzoo 时用的客户端名原是 `claude-code`，和用户自己的 Claude Code 共用浏览器身份，结果把用户正在看的标签页导航走了。改为 `unzoo-one-agent`，即独立身份。
- 待定：Unzoo 免费版只有 3 个浏览器身份，这台机器已用满，智能体建不了自己的身份。它没有借用别人的，而是停下来说明情况。需要决定 Unzoo One 的智能体怎么拿到身份（见第 7 节）。

### 3.6 不再有单独的引导

智能体装好且登录了就直接用。没有可用的，或选中的没登录，新对话页上方出现一张卡片，说明差哪一步（打开终端登录、重新检查）。

## 4. 第 2 步：智能体的电脑（概要）

- 对话右侧是一块可收起的“电脑”面板，有两个标签：终端、浏览器。
- **终端**：这一轮里智能体建的 unterm 会话（从 `session.create` 的结果拿 id），实时显示屏幕内容（`screen.read` 轮询）。
  - “在终端里打开”：把 Unzoo One 终端窗口切到这个会话，人直接接手。
  - 会话在对话结束后保留，下一轮智能体还能用（提示词里告诉它有哪些会话）。
- **浏览器**：智能体控制的 Unzoo 标签页，显示截图和网址，几秒刷新一次。
  - “在浏览器里打开”。
  - 遇到登录、验证码时，Unzoo 的 human_task 在这里提示人接手。
- 提示词：受管模式的系统提示里写明已有的终端会话、浏览器身份，让智能体主动复用。

### 4.2 实现与实测（2026-11-12）

- 运行时：
  - 每一轮记下智能体用过的终端（`terminals`）和标签页（`tabs`）：来自工具参数里的 `session_id`/`tab_id`，以及 `session.create`、`tab_create` 结果里的 id。只认 Unterm 和 Unzoo 的工具。
  - 新接口：
    - `POST /api/console/computer/terminal`：屏幕文字（`screen.text`）；
    - `/terminal/focus`：`session.focus`；
    - `/tab`：地址、标题和截图（Unzoo `/api/v1/tabs` + `/api/v1/screenshot`）；
    - `/tab/activate`：切到前台。
  - 只给看对话记录里出现过的终端和标签页。
- 控制台：
  - 对话头部有“电脑 · N”开关。智能体一用终端或浏览器，面板就自动打开，打开后保持。
  - 面板里分“终端”“网页”两类，运行中终端每 1.5 秒、网页每 3 秒刷新。
  - “在终端里打开”：桌面版没有终端窗口时先开一扇，再把会话切到前台；“在浏览器里打开”：切到 Unzoo 前台。
  - 窄屏时面板浮在对话上面。
- 实测：
  - 让智能体在终端里 `ping -n 20`，同时打开 example.com。面板自动打开，ping 输出逐行出现，网页截图正常；切网页到前台成功，切终端到前台成功。
  - 访问别的标签页会被拒绝：“not a tab an agent used”。
  - 追问“在同一个终端里 echo”，智能体复用了上一轮的终端会话 1，说明会话一直留在后台服务里。

### 4.1 智能体是中枢，其它智能体是它的工具

不自己做调度大脑：那要自带模型和费用，等于和 Claude 正面竞争。分工如下：

- **中枢**：用户选的智能体（默认 Claude Code）。它理解需求、拆步骤、决定用什么。
- **手和监督**：Unzoo One 提供终端、浏览器、技能，以及审批、风险分级、审计。
- **别的智能体**：通过 unterm 已有的 `agent_session.*` MCP 作为中枢的工具，比如把编码交给 Codex。同样走网关的 `Exec` 等级和审批。

用户只跟一个对话框说话。

## 5. 第 3 步：技能（概要）

- 采用开放的 Agent Skills 格式（文件夹 + SKILL.md），不自创。
- **自带技能**：终端（开服务并盯日志、长任务后台跑、读历史输出），浏览器（用某个身份登录后抓取、下载媒体、表格导出、遇到验证码交给人）。运行时启动智能体时挂上。
- **统一管理**：设置 › 技能。装一次，同步到各个 CLI 的技能目录（`~/.claude/skills`、Codex、agy 各自的位置）；能启用、停用、删除。
- **存为技能**：对话跑通后，“存为技能”让智能体把做法写成 SKILL.md（含用到的命令和网页步骤）。之后一句话或定时任务直接用它。
- Unzoo 已有的录制回放（`skill_list` / `skill_get`）作为浏览器技能的一种来源。

### 5.1 实现与实测（2026-11-13）

- **怎么交给智能体**：Claude Code 的 `--plugin-dir` 只给这次会话挂一个插件。运行时每次启动 Claude Code 前，把启用的技能组装成插件 `unzoo-one`（`<状态目录>/agent-plugin/unzoo-one`），不写进用户自己的 `~/.claude`。智能体看到的技能名是 `unzoo-one:<技能>`。
- **自带技能**（`apps/unzoo-one/skills/`，随安装包装到 `unterm-core.exe` 旁的 `skills/`，开发时用 `UNTERM_BUILTIN_SKILLS`）：
  - `unzoo-terminal`：终端会话复用、短命令和长任务的区别、读输出、交互程序、被拒后怎么办；
  - `unzoo-browser`：先开自己的标签页、用快照和提取工具、可靠输入、下载、登录和验证码交给人；
  - `unzoo-deliverables`：成果写在工作文件夹、文件命名和格式、回复怎么写。
- **你的技能**：放在 `<状态目录>/skills/<名字>/`，可以导入一个含 SKILL.md 的文件夹，或者从对话存下来。可以开关、删除（自带的只能关）。开关状态存在 `skills.json`。
- **存为技能**：对话“更多 › 存为技能”会在同一段对话里多跑一轮，让智能体把做法写进 `.unzoo-skill/<名字>/SKILL.md`。运行时在这一轮结束时把它收进技能库、删掉这个文件夹（不算成果），对话里显示“已存为技能”。
- **其它智能体**（2026-11-14）：Codex 和 OpenCode 也挂上同一套技能，同样只对这次会话、不写它们自己的配置：
  - Codex：运行时在 app-server 握手后发 `skills/extraRoots/set`，指向组装好的技能目录（会话环境变量 `UNTERM_SKILL_ROOTS` 告诉宿主）；
  - OpenCode：会话环境里的 `OPENCODE_CONFIG_CONTENT` 加 `skills.paths`，和用户自己的配置合并；
  - 续接对话时重新交一次（环境变量不随旧会话保留）；帮手走同一条启动路径，也有技能；
  - 实测：真的 Codex 列出了 unzoo-browser、unzoo-deliverables、unzoo-terminal；`opencode debug skill` 在同样的配置下列出这三个。agy 本机没装，没做。
  - 自带的终端、浏览器技能写的是 unterm / unzoo 的 MCP 工具；Codex、OpenCode 不受管时不一定接了这些工具，它们照常用自己的。
- **接口**：
  - `GET /api/console/skills`；
  - `POST /api/console/skills/toggle`、`/delete`、`/import`；
  - `POST /api/console/tasks/run` 新增 `save_skill`。
- **实测**：
  - 隔离服务认到 3 个自带技能，启动命令里带上了 `--plugin-dir`，插件里有 3 个技能。
  - 一个“查 Node 版本写进文件”的对话点“存为技能”后，得到 `record-node-version`：有输入参数、步骤、出错处理，没有被当成成果。
  - 新对话里只说“帮我记录一下 Node 版本”，智能体就调用了 `unzoo-one:record-node-version`，照着做完。

## 6. 第 4 步：对外提供 MCP（概要）

- 设置 › 接入：一键把 Unzoo One 的终端和浏览器 MCP 写进 Claude 桌面版、Claude Code、Cursor、Codex 的配置。
- 外部客户端的调用照样经过网关、按自主程度放行、进收件箱、留审计。

### 6.1 实现与实测（2026-11-13）

- **审批进收件箱**：外部客户端经终端写入、或做无法撤销的操作时，运行时原来要在终端窗口里弹确认；没有窗口就直接拒绝。现在规则是：
  - 有窗口，照旧问窗口；
  - 没有窗口、但控制台 90 秒内取过待审批列表（`note_console_watching`），就把问题挂进本地队列，至少等 2 分钟；
  - 控制台用 `approval.decide` 回答（只有进程内调用能答，外部智能体答不了自己的问题）；
  - 两者都没有才拒绝。
- **识别来源**：桥接程序（`unterm-cli mcp-stdio`）在握手时记下 MCP 的 `clientInfo`，第一次调用工具前发 `agent.identify`。收件箱里显示的是“Claude Desktop 请求在终端里执行”，不再是 anonymous；审计和“总是允许”也按客户端区分。
- **一键接入**：设置 › 能力 › 接入其它 AI 客户端。
  - 列出本机装了的 Claude Desktop、Claude Code、Cursor、Codex、Windsurf、Antigravity、Gemini CLI、OpenCode、Kimi、Qwen；
  - 终端以产品名 `unzoo-one` 写进它们的 MCP 配置，或者移出：只动这一条，同一个桥接程序的旧条目一并去掉，经临时文件写入，配置坏了就报错、不覆盖；
  - 浏览器的接入状态只读，“接入 Unzoo 浏览器”运行 Unzoo 自己的 `setup-mcp.ps1`：它会接入所有客户端，并备份后移除其它浏览器自动化工具，界面上写明了这一点。
- **接口**：
  - `GET /api/console/clients`；
  - `POST /api/console/clients/connect {id, connect}`；
  - `POST /api/console/clients/browser`；
  - 控制台额外轮询 `GET /api/approvals` 取外部客户端的确认，用 `POST /api/approvals/decide` 回答。
- **实测**（隔离服务，用临时家目录 `UNTERM_CLIENTS_HOME`，没碰真实配置）：
  - 认到 Claude Desktop、Claude Code、Cursor、Codex 四个客户端；点“接入终端”后，Claude Desktop 的配置里多了 `unzoo-one`；
  - 用这条配置里的命令模拟 Claude Desktop 执行 `echo`：请求进了收件箱，显示“Claude Desktop 请求在终端里执行”；
  - 批准后命令执行并把结果返回；另一次点拒绝，客户端收到 refused，命令没执行。
- **外部客户端也按自主程度**（2026-11-15）：原来外部客户端只在第一次写终端时问一次，之后同一客户端写什么都放行，分不出 `ls` 和 `rm -rf`。现在 Unzoo One 把设置里的自主程度交给运行时（`set_client_autonomy`），每次写入按方法和命令内容里更高的风险判断（`command_risk`）：
  - 在自主程度以内的直接执行，审计记 `mcp.confirm.autonomy`；不需要有人在场，所以 Unzoo One 没打开时普通命令也能跑；
  - 超出的每次都问（删除、强推在任何一档都问）；“总是允许”按这次的风险等级记成授权，不再放行这个客户端之后的所有写入；
  - 实测（隔离服务，没开控制台，模拟 Claude Desktop）：`echo` 1 秒执行；`rm -rf`、`git push --force` 被拦下，提示请用户打开 Unzoo One 再试；
  - 没有设置来源时（单独用 unterm）仍是原来的规则。
- **外部客户端也拿到用法和技能**（2026-11-15）：
  - **连接时的说明**：桥接程序旁边有 `mcp-instructions.md` 时，`initialize` 的 `instructions` 用它，不用 unterm 自带的那段（那段讲的是“你在 Unterm 窗口里”）。Unzoo One 的版本约 300 token：终端常驻、开一个复用、短命令和长任务、交给人的输入、被拒后别换法子。文件首行 `<!-- product: Unzoo One -->` 也让服务没开时的提示变成“请用户打开 Unzoo One”。所有 MCP 客户端都适用。
  - **技能装进客户端**：接入终端时把启用的技能复制进客户端自己读技能的文件夹，断开时取回。实测各家读的位置：Claude Code `~/.claude/skills`；Codex `~/.codex/skills`（不读 `~/.agents/skills`）；OpenCode `~/.config/opencode/skills`（也读 `~/.claude/skills`、`~/.agents/skills`）。Claude Desktop、Cursor 等没有可写的技能文件夹，只有连接时的说明。
  - 只动自己装的：每份复制里放 `.unzoo-one-skill` 标记；同名而没有标记的文件夹是用户自己的，跳过并报告；技能开关、导入、删除后，以及服务启动时（更新可能改了自带技能）同步已接入的客户端。`unzoo-deliverables` 只在 Unzoo One 跑的任务里有意义，不装。
  - 自带技能的措辞改成两边都对：服务器名 `unterm` / `unzoo-one`；`agent_session.handover` 只在托管任务里有，没有时在回复里请用户在那个标签页操作。
  - 实测（隔离服务、临时家目录）：接入三个客户端后各装了 `unzoo-browser`、`unzoo-terminal`；真的 Codex（app-server `skills/list`）和 OpenCode（`debug skill`）都列出了它们；断开 Claude Code 移除了这两个，用户自己的 `my-own` 还在；桥接程序初始化带上了 Unzoo One 的说明，服务没开时提示打开 Unzoo One。
- **对外发送、读取密钥也问**（2026-11-15）：原来中央的检查只拦“无法撤销”的方法，外部客户端调 `upload.file`（读本机任意文件、传到云存储、返回公开链接）不问就做。现在风险在“对外发送”及以上（对外发送、读取密钥、花钱、无法撤销）的方法都过这道检查：
  - 规则同终端写入：常设信任和“总是允许”的授权优先；自主程度允许的直接执行（放手档允许对外发送，任何一档都不允许读取密钥、花钱、无法撤销）；其余进收件箱，问题写明方法、对象和原因，例如“upload.file C:/work/report.pdf (sends something off this machine)”；没人能答就拒绝。
  - 托管会话的这类调用宿主已经问过，不再问第二次；无法撤销的照旧再问。
  - 收件箱按风险显示“把东西发出这台电脑”“读取你的账号或密钥”“花钱”，读取密钥和花钱标高风险。
  - 桥接程序等回复的时间从 45 秒改为至少 135 秒：控制台里的问题至少开 2 分钟，桥接先放弃会让人点了允许却没人接。
  - 自主程度只在由产品启动时生效（`UNTERM_PRODUCT_NAME` 不是 Unterm）；单独用 unterm 时外部写入仍按原规则，headless 第一次写入直接拒绝。
  - 实测（隔离服务，模拟 Claude Desktop 上传一个文件）：控制台没在看时直接拒绝并说明原因；在看时进了收件箱，拒绝后客户端收到 refused，允许后才进入上传（测试环境没配置存储，停在缺配置，没有发出任何东西）。
- **限制**：
  - 要确认的操作在 Unzoo One 没打开时会被拒绝（没人能答）；
  - 判断依据是一次写入的文字，把一条命令拆成几次按键输入能绕过命令内容的判断（方法本身的风险仍在）；
  - 判断依据只看方法和命令文字：`exec.run` 里一条 `curl` 上传按命令内容判断，能否认出取决于 `command_risk` 的规则。

## 7. 智能体的浏览器身份（2026-11-12 定）

Unzoo 要卖，额度照算：Unzoo One 发起的身份也计入额度，不开例外。两种拿到身份的方式：

- **预留**：智能体以客户端 `unzoo-one-agent` 连 Unzoo，对应的身份叫 `mcp-unzoo-one-agent`。控制台读浏览器状态时（设置页、新对话页），如果额度有空、又没有另外指定，运行时就把这个身份建好（`POST /api/v1/profiles/create {name}`），不等智能体第一次要用浏览器时才发现额度满了。
- **指定**：设置 › 智能体 › 浏览器身份，选一个现有身份，比如登录了你账号的那个。Unzoo 不能把客户端绑到某个身份上，但每个浏览器工具都接受 `profile_id`。运行时把身份写进智能体的系统提示：每次调用带上 `profile_id`，先 `tab_create` 开自己的标签页，之后只用这个标签页，不碰别的。
- **都没有时**：新对话页上方出现卡片“智能体还没有浏览器身份”，给出“选一个身份”和“升级 Unzoo”；设置里同样有“升级 Unzoo”。这也是 Unzoo 的购买入口。

接口：`GET /api/console/browser` 返回套餐、已用/上限、身份列表、专用身份是否已建、指定的身份、能否上网（`ready`）。运行设置新增 `browser_profile`。

实测：Free 版 3/3 已满时，卡片正常出现；在设置里指定测试身份后 `ready` 变为 true；浏览器任务在该身份里新开标签页、读出标题，用户正在看的标签页没被动过。

## 8. 中枢调度：帮手（2026-11-13）

落实 4.1：对话里的智能体是中枢，别的智能体是它的帮手。用户还是只跟一个对话框说话。

- **怎么交**：新 MCP 方法 `agent_session.delegate`（参数 `agent`、`prompt`、`session_id`、`wait_seconds`）。中枢交出一段完整的活，等帮手这一轮做完，拿回它的报告；超时就回 `working`，带着 `session_id` 再调一次接着等；做完后带 `session_id` 和新的 `prompt` 能让同一个帮手接着干。
- **帮手的条件不比中枢宽**：只有运行时托管的会话能调（凭托管凭证认出是谁在调）。帮手用中枢的工作文件夹、自主程度和任务编号，浏览器身份同运行设置。帮手不能再往下交；一个中枢最多 3 个帮手；中枢这一轮结束时，帮手一起停。
- **谁来批准**：帮手要问的，照样进对话（帮手卡片里就地回答）和收件箱，用帮手自己的会话回答。中枢替不了人：
  - 中枢自己调 `agent_session.start / resume / submit_input / decide`、`approval.decide`、`agent.trust / untrust`，在任何自主程度下都要问人。原来“平衡”档会自动放行这些，等于中枢可以绕开自己的限制起一个不受管的进程，或者替帮手点批准。
  - `delegate` 本身按“运行程序”算：平衡档自动，谨慎档要问。
- **中枢怎么知道**：受管的 Claude Code 的系统提示里加了一段说明：什么时候交、写清楚完整的 prompt、等帮手做完再结束、不要自己用 `agent_session.start`。帮手的提示里没有这段，开头说明它的最后一条消息就是交回给中枢的报告。
- **桥接等待**：`unterm-cli` 的桥接原来 45 秒没回就算超时；`delegate` 这一次调用按 `wait_seconds` 加 30 秒等。
- **对话里看到的**：中枢那一行显示“交给 Codex：……”；下面一张帮手卡片：名字、状态（正在做 / 等你确认 / 做完了 / 出错了 / 已停下）、交给它的活、它做了什么、它的回复，要确认的就地确认。帮手用过的终端和标签页也进“电脑”面板。
- **实测**（隔离服务，真的 Claude Code 当中枢、真的 Codex 当帮手，谨慎档）：让中枢“交给 Codex 建一个 hello.txt”。中枢请求交给 Codex，进了待确认，批准；Codex 要运行一条 PowerShell 写文件，以帮手的问题出现，用帮手的会话批准；21 秒后帮手做完，中枢转述了 Codex 的报告，`hello.txt` 内容正确、出现在产出里；这一轮结束后没有残留的 Codex 进程。
- **限制**：
  - 只有受管的 Claude Code 能当中枢（只有它有托管凭证）；
  - Codex 等不受管的帮手用自己的 shell，不走 Unzoo One 的终端，“电脑”面板里看不到它的命令，只在帮手卡片里看到；
  - 帮手卡片的界面这次只用单元测试和类型检查验过，没在真窗口里看过。

## 9. 关掉 unterm 的自动 setup-ai（2026-11-13）

unterm 的终端窗口第一次启动时会自动跑 `setup-ai`，往本机所有 AI 客户端写一条叫 `unterm` 的服务，并往 `~/.claude/CLAUDE.md` 这类文件里写一段介绍。由 Unzoo One 启动时（`UNTERM_PRODUCT_NAME` 不是 Unterm）不再自动跑：接入哪些客户端由设置 › 能力 › 接入其它 AI 客户端决定。手动的 `unterm-cli setup-ai` 还在。已经写进用户配置的旧条目，在设置里点一次“接入终端”会被替换成 `unzoo-one`。

## 10. 请人接手：登录、验证码（2026-11-14）

第 2 步写了“遇到登录、验证码时提示人接手”，原来交给了 Unzoo 的 `human_task`。查下来它不是“交给人”，而是按人的节奏自动点击、输入的一串步骤；自带的浏览器技能让智能体用它“把标签页交给人”，等于让它自己去点登录表单。现在由运行时提供：

- **新 MCP 方法** `agent_session.handover`（参数 `what`、`tab_id`、`handover_id`、`wait_seconds`）：智能体用一句话说请人做什么、在哪个标签页，然后等。人点“好了，继续”或“做不了”，调用返回 `done` / `cannot`（带人写的话）；一次最多等 10 分钟，没答就回 `waiting`，带 `handover_id` 再调接着等，卡片一直在。
- 只有运行时托管的会话能调；只是问人、不运行任何东西，网关按只读算，任何自主程度都不另外确认。
- 受管的智能体系统提示和自带的浏览器技能都写明：登录、验证码、手机确认、密码和卡号，一律交给人，不自己输入，也不在对话里要。
- **对话里**：这一轮下面出现“它在等你接手”卡片：要做的事、“在浏览器里打开”（有标签页时）、可选的一句话、“好了，继续”“做不了”。答完收成一行“你接手做完了：……”。对话列表显示“等你确认”，等人时不算卡住。
- **接口**：`POST /api/console/handover {session_id, handover_id, done, note?}`。
- **实测**（隔离服务，真的 Claude Code，平衡档）：让它“先请我在手机上确认登录，再写 done.txt”。9 秒后卡片出现，没有任何确认；在卡片上点“好了，继续”后它接着写了文件、回复，这一轮正常结束。
- **限制**：Codex 等不受管的帮手不能调（没有托管凭证）；帮手卡片里还不显示帮手的接手请求。

## 11. 手机（2026-11-16）

单机版不架服务器：手机和电脑在同一个 Wi-Fi，或都装了 Tailscale，直接连电脑。用的是内核原有的远程通道（只放行局域网、Tailscale 和本机地址；配对码换每台设备自己的令牌，令牌只存哈希，可撤销）。云端中转（Cloudflare Workers + Durable Objects，端到端加密）研究过，先不做。

- **手机页**：产品名不是 Unterm 时，远程通道的首页换成产品自己的手机页（`unterm-settings/assets/mobile/product.html`），单机版的终端驾驶舱页保持不变。中英文按手机语言。
  - "等你处理"：受管智能体的问题、外部客户端的确认、"请你接手"，就地允许 / 拒绝 / 好了继续 / 做不了。手机上拒绝 = 拒绝并停下这一轮，和控制台一样。
  - 对话列表和每段对话；发新任务、接着说、停止。手机上开的对话以控制台的格式存，电脑上照常出现。
  - 有新的待处理时手机振动、标题带数字。局域网是 http，浏览器推送用不了。
- **接口**（远程通道上，需设备令牌）：`GET /api/one/overview`，`POST /api/one/thread | send | decide | handover | stop`（`unterm-settings/src/mobile_one.rs`）。全部转给控制台用的同一批函数，手机做不了控制台做不了的事。只读配对的设备只能看。
- **手机开着也算"有人在看"**：读一次总览就记一次，外部客户端要确认的操作在 90 秒内等手机回答，而不是直接拒绝。
- **配对码**：每个码最多错 5 次，错满即作废。
- **电脑端**：设置 › 能力 › 手机：配对一台手机（每个局域网 / Tailscale 地址一个二维码和配对码，2 分钟有效）、已配对的手机和上次连接时间、取消配对、关闭手机连接。
- **实测**（隔离服务，真的 Claude Code，平衡档；"手机"用电脑的局域网地址访问）：
  - 配对：错码 400，对码拿到令牌；不带令牌 401；同一个码错 5 次后对的码也配不上。
  - 从手机发"建 phone.txt 再用 Remove-Item 删掉"：删除命令出现在手机的"等你处理"，手机上允许，52 秒后做完、回复正确。
  - 外部客户端（模拟 Claude Desktop）上传文件：没人看时没做；手机开着时确认出现在手机上，手机拒绝，客户端收到"用户拒绝"。
  - 智能体请"在手机上确认登录"：接手卡片出现在手机上，点"好了"后它接着回复。
  - 在 Unzoo 浏览器里打开配对链接：自动配对，对话列表和对话页正常显示。
- **限制**：
  - 只在局域网 / Tailscale 里能用；在外面又没装 Tailscale 的连不上。
  - 没有推送：手机页不开着就不知道有事要批。
  - Windows 防火墙第一次可能要用户点允许（专用网络）。
  - 没在真手机上试过，只用电脑浏览器访问局域网地址验证。
  - 帮手的接手请求不在手机上显示（和控制台一样）。


## 12. OpenCode 受管时的批准（2026-11-17）

实测（隔离服务，真的 OpenCode 1.19.5，平衡档，从手机发“建一个文件再用 Remove-Item 删掉”）发现两个洞，已补：

- **OpenCode 默认不问就跑 MCP 工具**：受管时它的终端就是我们的 MCP，删除命令一次都没问。受管预设加上 `permission: {"unterm_*": "ask", "unzoo_*": "ask"}`（按挂上的服务生成）。
- **它问的时候不带参数**：直接对 `opencode acp` 实测，`session/request_permission` 的 `rawInput` 是空的 `{}`，命令要等批准后的 `tool_call_update` 才有。宿主看不到命令，只能按“运行程序”放行。
  - 改法：受管会话里，往终端写入（`exec.run` / `exec.run_wait` / `exec.send` / `session.input` / `session.paste`）却不带命令的请求，宿主放行（`decided_by: "terminal"`），并把这个会话标成“终端来判断”。
  - 终端写入的检查原来对受管会话一律放行（宿主问过了）；现在对这种会话按命令本身判断，用会话自己的自主程度，超出的进确认队列（控制台收件箱、手机上的“确认”），显示完整命令。
  - Claude Code、Codex 问的时候带着命令，照旧由宿主判断。
- 拒绝写入时给智能体的话原来写“在 Unterm 窗口里拒绝”，智能体会照搬给用户；改为产品名。
- **实测**：
  - OpenCode：建文件自动放行；删除命令进了手机的确认，显示完整命令；允许后删掉了，拒绝后文件还在，它在回复里如实说被拒了。
  - Codex 同样的任务：问题带着完整命令出现在手机上，不受影响。
- **限制**：这种确认走的是外部客户端那条队列，控制台和手机都没人在看时直接拒绝，不像宿主的问题那样一直等。

## 13. 和单独安装的 Unterm 共存（2026-11-18）

原来两边共用一个后台服务：状态都在 `~/.unterm` 和 `%LOCALAPPDATA%\Unterm`，谁先启动谁的服务就被另一边连上。本机就是这样：Unzoo One 连着单独安装的旧版 Unterm 的服务，新功能都没生效，名字、文件夹、自主程度也按 Unterm 走。两者使用场景不同（Unterm 是给开发者的终端，Unzoo One 是给用户的智能体电脑），改为各用各的：

- **按产品分目录**（`unterm-protocol`）：产品名不是 Unterm 时，状态在 `~/.<产品名>`（`~/.unzoo-one`），后台服务的记录和锁在 `%LOCALAPPDATA%\<产品名>`（`%LOCALAPPDATA%\Unzoo One`）。`UNTERM_STATE_DIR` 照旧覆盖两者。
- **产品名从哪来**：`UNTERM_PRODUCT_NAME`；没有时看程序旁边的 `unterm-product.txt`。安装包里放了这个文件，所以 AI 客户端启动的桥接程序（没人给它环境变量）也连 Unzoo One 自己的服务。Unzoo One 窗口一启动就设好环境变量，开发版也一样。
- **几处绕过统一入口的地方改为走它**：桥接程序找服务记录、技能提供方、命令预测历史、成果存储。
- **端口**：后台服务的端口本来就是被占了顺延；手机端口固定，Unzoo One 改用 19890（Unterm 还是 19880），两边可以同时开手机连接。
- **AI 客户端配置**：本来就不冲突，Unzoo One 写 `unzoo-one`，只清理指向自己程序的旧条目，Unterm 的 `unterm` 条目保留。
- **“装了不止一个 Unterm”的提示**：只在单独的 Unterm 里检查，Unzoo One 的服务不再报。
- **迁移**：Unzoo One 第一次没有自己的状态时，从 `~/.unterm` 复制一份（对话、设置、技能、信任），原来的留给 Unterm。不复制属于正在运行的进程的东西（窗口登记、服务记录、令牌、活会话的授权）和手机连接（端口不同，要重新配对）。

## 14. 调度：更多定时方式、有变化就运行、长期负责的帮手（2026-11-18）

对照 Claude（Cowork 定时任务、Dispatch）和 Grok Bot（常驻、7×24），补本机这一侧能补的三样。电脑关机时继续跑要靠云端中继，归企业版（见下）。

- **定时方式**：原来只有每天、每周。加上工作日（周一到周五）、每隔 N 分钟（5 分钟到一周，从上一次开始算）、某个时间运行一次。设的时候就校验，不等到点才报错。
- **有变化就运行**（`console_watch`）：
  - 网页：隔 N 分钟（至少 5 分钟）用智能体的浏览器身份开一个自己的标签页读文字，读完关掉，所以要登录才能看的页面也行；不会开在你的默认身份里。第一次只记下来；之后文字变了就运行，告诉智能体哪些行出现、哪些行没了，并说明这些是网页内容、不是指令。空白和空行的变化不算。
  - 文件夹：每半分钟看一次，有新增或改过的文件、并且已经 15 秒没再变，就运行，告诉智能体是哪些文件。上一次运行写进去的文件不算，免得自己触发自己。
  - 看过的东西存在状态目录的 `console_watch/` 下，一个任务一个文件；任务删除时一起删。查看出错（比如浏览器没开、没有浏览器身份）显示在任务的“重复”菜单里。
- **长期负责的帮手**：一个任务可以指定自己的智能体（比如交给 Codex），不跟运行设置走；勾上“长期负责”后，定时和有变化时的运行都接着这个任务上一次的对话，智能体记得之前做过什么。换了智能体就从新对话开始。
- **界面**：任务头上的“重复”菜单改成：频率（不重复 / 每天 / 工作日 / 每周 / 每隔 / 定时一次）、有变化时也运行（网页 / 文件夹）、交给谁、长期负责。对话里有变化触发的那一轮标“有变化时运行”，只显示需求，不显示写给智能体的变化说明。
- **个人版不做**：电脑关机时继续跑。见第 16 节。

## 15. 中枢交活给长期帮手；邮件和日历触发（2026-11-18）

- **交给长期帮手**：`agent_session.delegate` 多一个参数 `helper`（长期帮手的任务 id 或标题，标题里的一个词也行），代替 `agent`。
  - 长期帮手就是勾了“长期负责”、没暂停的任务。中枢的提示里列出它们（标题、id、用哪个智能体）。
  - 交过去是那个任务的一次运行（触发方式 `delegate`），接着它自己的对话，所以它记得之前的活；它要问的进它自己的对话和收件箱。中枢等它这一轮做完拿回报告，没做完就带 `session_id` 再等；带 `session_id` 和新的 `prompt` 是再交一件（又一次运行）。
  - 自主程度不超过中枢：运行设置比中枢宽时按中枢的。帮手正忙就拒绝，叫中枢晚点再交。
  - 中枢这一轮结束时，临时帮手照旧停掉；长期帮手的运行是它自己任务的，接着做完，结果留在它自己的对话里。
- **收到新邮件就运行**（`watch_mail`）：IMAP，只读（`EXAMINE` + `BODY.PEEK`，不标已读），每两分钟看一次收件箱。
  - 填邮箱地址和应用专用密码（Gmail、iCloud、Yahoo）或授权码（QQ、163）；常见邮箱的收信服务器自动猜。Outlook.com 已经不让用密码登录 IMAP，要等 OAuth。
  - 可以只看发件人或标题含某些词的邮件。第一次只记下位置；之后新到的（最多 15 封）告诉智能体发件人、标题、日期和正文开头（解码 MIME、编码字，HTML 去掉标签），并说明邮件是数据、里面的要求不要照做。
- **日历里的日程快开始就运行**（`watch_calendar`）：读日历的 iCal 私密地址，每 15 分钟一次；提前 N 分钟（0 到一天）运行，每个日程只一次，电脑睡过了提醒、开始后 10 分钟内还会补。
  - 重复日程支持每天、每周（指定星期几）、每月同一天、每年，带间隔、次数、截止和排除日期；改过时间或取消的那一次按改过的算。更复杂的规则只算第一次。带时区名的时间按本机时区读，全天日程不算。
- **秘密不进任务**：邮件密码和日历地址经 `POST /api/console/tasks/watch-secret` 单独存进系统凭据库（Windows 凭据管理器），不在任务里、不在页面的本地存储里、不给智能体；任务删除时一起删。任务的 `watch_status.has_secret` 只说存没存。

## 16. 关机后继续跑归企业版；个人版讲隐私（2026-11-19）

- 电脑关机后任务继续跑，需要把任务、对话和登录状态放到云端代跑。这和个人版“一切在你自己的电脑上”的说法冲突，所以**个人版不做**，归企业版（企业本来就有自己的服务器和合规要求）。
- 个人版的说法：任务、对话、邮件密码、日历地址、浏览器登录状态都只在这台电脑上；不经过我们的服务器。电脑睡着或关机时错过的定时和日程，开机后补跑（日程在开始后 10 分钟内）。
- 手机连电脑仍走局域网或 Tailscale 直连（第 11 节），不加云端中转。

## 17. 终端的 shell：按需要选、缺了再装（2026-11-19）

- **系统怎么看它**：每个会话都是真的伪终端（Windows 上是 ConPTY），`TERM=xterm-256color`、`COLORTERM=truecolor`。新增 `TERM_PROGRAM`：默认是产品名去掉空格（Unzoo One 里是 `UnzooOne`，单独的 Unterm 是 `Unterm`），版本在 `TERM_PROGRAM_VERSION`。从父进程继承来的（比如 `vscode`）不往下传，调用方特意设的保留。之前设置页的“终端名”存了但从没生效。
- **不注册成 Windows 的默认终端**：那要实现 Windows Terminal 的 COM 交接接口（`ITerminalHandoff`），工作量大，先不做。
- **默认 shell**：有 PowerShell 7 用它，否则 Windows PowerShell；设置里可以换（写进配置的 `shell = [...]`），改完立即对新终端生效，不用重启后台服务；选“自动”删掉这一行。
- **智能体按需要选**：智能体开始时拿到一句话——默认是哪个、本机还有哪些（带可以直接用的 argv）、缺的怎么装。要别的 shell 就用 `session.create` 的 `argv`。`session.create` 只给命令字符串时仍按原样走 `cmd /C`（上游的调用方和测试都按 cmd 语法写，改了会破坏接口），说明里写清楚，并让智能体要别的 shell 时用 `argv`。
- **缺了再装，先问人**：网关把装卸整机程序单列出来：`winget/choco/scoop/brew/apt/dnf/pacman… install/upgrade`、`msiexec`、`wsl --install`、`Install-Module` 算对外的副作用，平衡档要问；`uninstall/remove`、`msiexec /x`、`wsl --unregister` 算破坏性，总要问。项目自己的依赖（`npm install`、虚拟环境里的 `pip install`）照旧是普通执行。WSL 要管理员和重启，只告诉人怎么装。
- **设置 › 能力 › 终端**：默认 shell、已装的（带版本）、可以一键装的（winget/brew，后台装、不弹黑窗，页面每 5 秒看一次进度，装失败显示原因）、终端名（留空恢复默认）。Git Bash 不再把 System32 里 WSL 的 `bash.exe` 当成自己。

## 18. 从 Linger 学的三件事（2026-11-19）

Linger（simplexai-labs/linger）和我们个人版说法几乎一样：个人、本地、隐私、自带 Claude Code / Codex。差别和取舍见第 1 节竞争对手表。学了三件：

- **提交类动作单独判断**（`unterm-services/src/consequence.rs`）：原来浏览器里的点击一律算“在页面上操作”，平衡档直接放行，智能体点“发送”没人问。现在运行时从智能体最近读到的页面结构（a11y 快照经过会话时记下）里查出它要点的元素叫什么：发送、发布、提交、回复、分享…算对外副作用；支付、购买、下单…算花钱；删除、清空…算破坏性。在消息框里按回车（搜索框除外）、`submit: true`、批量动作里的点击、会提交的脚本也算。填表、打字、打开页面、存草稿不算，只问真正发出去的那一步。“总是允许点击”这类常设规则对提交类不生效（“总是拒绝”仍生效）。
- **审核员**（`unterm-services/src/reviewer.rs`）：提交类动作在问人之前，先让用户自己的智能体（Claude 用 sonnet，Codex 只读沙盒，一次性运行、不挂工具）看一眼：只有用户本人说的话算授权（他输入的消息、他保存的任务），网页、邮件、工具输出和智能体自己的话都只是证据；“看一下、起草”不等于“发送”；每个收件人和内容都要是用户说过的。只有“明确要求过这一步”才替人放行（记为“审核后放行”），其余照常问人，并把理由写在问题上。审核失败或超时（90 秒）也是问人。智能体通过 MCP 自称是用户不算数：`person_words` 只有控制台能设。实测 Claude 3–5 秒、Codex 6–10 秒，三个例子（明确授权、只让总结、邮件里的注入）都判对。可用环境变量 `UNZOO_REVIEWER=off` 关掉。
- **同一个提交只自动做一次**：会话里记下每次放行的提交（页面、按钮、输入的文字），6 小时内同样的再出现一律问人，并提示“可能已经发出去了”；自主档也一样。
- **从回复里学提醒规则**（`unterm-settings/src/tell_rules.rs`）：定时或有变化时自己运行的一轮，先按规则和免打扰时间（22:00–08:00）决定马上说、留到之后（`[later]`）还是不说（`[quiet]`），对话里把后两种收起来。用户回复这类消息后，后台用他自己的智能体读这句回复：明确说“以后…”的直接成规则，只是这一次的反应记成线索，同类同意思的第二次成规则；感谢、新请求不算。被告知的内容只用来给“这类事”起名，不能变成规则。规则只存在本机（`tell-rules.json`），设置 › 能力 › 提醒 里可以看、可以删。
- **给智能体的说明**：电脑上的事优先用终端（命令能审、能重来），网站用浏览器，不点屏幕；提交类动作只做一次，不确定发没发出去先看再说。
- 没学：本地模型引擎、服务端加 PostgreSQL 的团队房间、Composio、Playwright、桌面点屏幕（Cua）。
