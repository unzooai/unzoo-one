# Unzoo One 分发、数据与运行保障规范

> 状态：产品规格草案
> 目标版本：Private Alpha → Public Beta
> 目的：让 Unzoo One 可以安全安装、持续升级、长期运行、完整迁移，并在故障时可恢复。

## 1. 产品运行形态

Unzoo One 是一个本地优先的桌面产品，不把自身实现成另一个超大单体。桌面端负责统一体验与策略，能力由可独立升级的运行时提供。

| 组件 | 主要职责 | 默认网络暴露 |
| --- | --- | --- |
| `unzoo-one-desktop` | UI、任务编排、策略、审批、数据索引 | 无公网监听 |
| `unzoo-one-supervisor` | 进程拉起、健康检查、版本协调、崩溃恢复 | 仅本机 IPC |
| `unterm` | PTY、命令执行、会话、无头代理运行时 | 仅本机认证接口 |
| `unzoo` | 浏览器、Profile、Computer Use、下载与网页证据 | 仅本机认证接口 |
| Brain Adapter | Codex、Claude 或本地模型的统一适配 | 按供应商出站 |
| Connector Runtime | 外部服务连接、Webhook 与定时同步 | 按授权出站/入站 |
| Local Vault | 凭据与敏感配置加密存储 | 无 |

桌面进程退出不应自动终止正在安全执行的后台任务。Supervisor 保持任务运行，并在桌面重新打开后恢复事件流。

## 2. 支持平台

### 2.1 发布顺序

1. Windows 11 x64：Private Alpha 首发。
2. macOS Apple Silicon：Public Beta 前支持。
3. Linux x64：根据 Unterm、Unzoo 的平台成熟度进入 Beta。

### 2.2 最低运行要求

- 8 GB 内存，推荐 16 GB。
- 5 GB 可用磁盘空间，不含下载、浏览器 Profile 和模型。
- 可访问至少一个 Brain Provider，或已安装兼容的本地模型。
- 操作系统安全存储可用；不可用时禁止保存长期凭据。

不把 Git、Python、Node.js、浏览器驱动等开发依赖暴露给普通用户。正式安装包必须包含或自动管理所需运行时。

## 3. 首次安装与引导

### 3.1 安装流程

1. 验证安装包签名。
2. 安装 Desktop 与 Supervisor。
3. 探测已安装的 Unterm、Unzoo 及版本。
4. 安装缺失的受信任组件，或提示用户选择现有开发版。
5. 建立本机 IPC 身份与双向认证材料。
6. 运行 Self-test。
7. 进入首次引导。

安装器不得静默改变系统代理、默认浏览器、Shell Profile 或全局 Git 配置。

### 3.2 首次引导

首次引导最多五步：

1. 选择 Brain：Codex、Claude、本地模型或稍后设置。
2. 登录或配置凭据。
3. 选择默认工作目录。
4. 选择安全模式：默认 `Standard`。
5. 运行“整理一个示例目录”或“研究一个公开网页”的演示任务。

完成标准：用户在十分钟内获得第一个可查看 Artifact，并能理解任务做了什么、访问了什么、如何撤销。

### 3.3 Self-test

Self-test 输出结构化结果，不只显示“失败”：

- Desktop ↔ Supervisor 通信。
- Unterm 版本、PTY 创建、只读命令和事件回传。
- Unzoo 版本、浏览器启动、页面快照和截图。
- Brain 鉴权、最小推理请求和取消请求。
- 数据库读写、Vault 加解密。
- 本地端口冲突、磁盘空间、系统时间。

每个失败项必须提供：影响范围、自动修复、手动修复和诊断详情。

## 4. 版本与兼容性

### 4.1 版本清单

Desktop 随包携带签名的兼容性清单：

```json
{
  "productVersion": "0.1.0",
  "protocolVersion": "v0",
  "components": {
    "unterm": { "min": "0.8.0", "tested": "0.9.1", "maxExclusive": "1.0.0" },
    "unzoo": { "min": "2.2.0", "tested": "2.3.0", "maxExclusive": "3.0.0" }
  },
  "brainAdapters": ["codex-sdk-v1", "claude-agent-sdk-v1"]
}
```

版本不兼容时，不允许“带病运行”高风险能力：

- 轻微版本偏差：降级为兼容模式，并显示缺失能力。
- 协议不兼容：阻止启动对应 Provider。
- 安全修复缺失：进入 Safe Mode，直到升级或用户显式退出该组件。

### 4.2 能力协商

所有 Provider 启动后返回 Capability Manifest，包括：

- 协议版本。
- 可用 Action。
- 支持的审批暂停与恢复语义。
- 支持的证据类型。
- 最大并发、取消和超时能力。
- 实验性能力及稳定性等级。

UI 只展示当前环境真正支持的功能，不能用静态开关伪装可用性。

## 5. 更新、回滚与发布通道

### 5.1 更新通道

- `stable`：默认，分阶段发布。
- `preview`：提前体验已完成内部验证的功能。
- `developer`：允许连接本地构建，仅面向开发者。

### 5.2 更新原则

- 安装包、差分包和兼容性清单全部签名。
- 下载完成后再次校验哈希与签名。
- 更新前检查正在运行的任务；不可安全暂停时延后更新。
- 数据迁移前创建恢复点。
- 更新后运行快速 Self-test。
- 更新失败自动回滚二进制与兼容的数据快照。

### 5.3 分阶段发布

`内部 → 5% → 25% → 100%`。任一阶段出现以下情况自动停止扩量：

- 启动失败率超过 1%。
- 崩溃率相对上一稳定版增加 30%。
- 数据迁移失败率超过 0.1%。
- 安全或权限回归出现一例可复现高危事件。

### 5.4 数据库迁移

迁移必须：

- 有唯一 ID、前置版本与目标版本。
- 尽量向后兼容一个稳定版本。
- 可重复执行，或能检测已执行状态。
- 在真实规模脱敏数据集上验证。
- 明确不可逆字段，并在更新前创建完整备份。

## 6. 本地数据模型与目录

建议逻辑目录：

```text
Unzoo One/
├── config/          # 非敏感配置
├── database/        # 任务、事件、索引和元数据
├── artifacts/       # 用户可交付结果
├── evidence/        # 截图、终端片段、变更摘要
├── automations/     # 自动化定义
├── skills/          # 已安装 Skill
├── connectors/      # Connector 描述与非敏感状态
├── logs/            # 滚动日志
├── backups/         # 本地恢复点
└── cache/           # 可安全重建的缓存
```

凭据、Token、Cookie 加密密钥不得存入以上普通文件；它们进入操作系统安全存储或 Local Vault。

### 6.1 数据所有权

- 用户创建的 Artifact 永远属于用户，可通过普通文件系统访问。
- 对话、任务和自动化可完整导出。
- 用户可删除单个任务、单个连接器、全部记忆或整个本地账户。
- 产品卸载不得默认删除用户 Artifact。

### 6.2 保留策略

默认建议：

| 数据 | 默认保留 |
| --- | --- |
| Task 与 Run 元数据 | 永久，直到用户删除 |
| 审计事件 | 90 天 |
| 终端完整输出 | 30 天 |
| 网页截图与证据 | 30 天 |
| 诊断日志 | 14 天 |
| 可重建缓存 | 最多 7 天 |

用户可以缩短保留期。受调查保护的安全事件应单独标记，避免被常规清理误删。

## 7. 导出、备份、迁移与卸载

### 7.1 导出级别

1. 单任务包：任务、步骤、审批、Artifact 与证据。
2. 工作区包：指定目录关联的任务、自动化与记忆。
3. 完整账户包：所有可迁移数据。

导出包默认不包含凭据和浏览器 Cookie。用户显式选择“包含敏感会话”时，必须使用独立密码加密并显示风险。

### 7.2 备份

- 自动恢复点：重大升级前。
- 手动备份：随时创建。
- 可选计划备份：每日或每周，保留数量可配置。
- 备份完成后执行可读性校验。

### 7.3 恢复

恢复前展示：

- 包版本与创建时间。
- 将新增、覆盖或跳过的对象。
- 不兼容项。
- 凭据需要重新授权的连接器。

恢复过程采用临时数据库验证，通过后再原子切换。

### 7.4 卸载

卸载器提供三个明确选项：

- 仅移除应用，保留数据。
- 移除应用与缓存，保留 Artifact 和导出。
- 删除全部本地数据；要求二次确认并显示绝对路径。

## 8. 可观测性与诊断

### 8.1 本地日志

每条日志至少含：

- 时间、组件、版本和严重级别。
- `taskId`、`runId`、`traceId`，如适用。
- 稳定错误码。
- 已脱敏的上下文。

禁止记录：

- API Key、Cookie、Authorization Header。
- 用户输入或文件全文。
- 未脱敏的终端环境变量。
- 密码输入框内容。

### 8.2 Support Bundle

用户可一键生成诊断包，生成前预览其内容：

- 版本与能力清单。
- Self-test 结果。
- 最近错误和崩溃信息。
- 脱敏日志。
- 可选的指定 Task 事件时间线。

默认排除 Artifact 内容、屏幕截图、浏览器历史和凭据。任何内容级材料都必须逐项勾选。

### 8.3 遥测

Private Alpha 默认仅本地记录产品指标。远程遥测必须显式同意，并满足：

- 不发送提示词、文件内容、网页内容和终端输出。
- 使用随机安装 ID，可随时重置。
- 设置页可查看最近发送的事件。
- 关闭后立即停止，不以“必要 Cookie”名义继续发送产品分析数据。

允许的最小事件包括安装成功、页面打开、任务状态变化、错误码、耗时分桶和功能开关，不含用户内容。

## 9. 性能目标与容量

Private Alpha 的工程目标：

| 指标 | 目标 |
| --- | --- |
| 冷启动到可交互 | P95 < 5 秒 |
| 从提交任务到出现首个状态 | P95 < 1 秒 |
| 审批响应到任务恢复 | P95 < 1 秒 |
| 前台事件延迟 | P95 < 500 毫秒 |
| Desktop 崩溃后任务恢复 | < 10 秒 |
| 连续空闲内存 | Desktop + Supervisor < 800 MB，不含浏览器与模型 |
| 事件历史加载 | 10 万事件下首屏 < 2 秒 |

大输出必须流式写入磁盘并分页读取，禁止把完整终端输出、网页 DOM 或模型上下文长期保存在 UI 内存中。

## 10. 资源与后台任务管理

- Provider 声明并发上限，由 Supervisor 统一调度。
- 高 CPU、内存、网络或磁盘任务显示资源徽标。
- 电池供电时可暂停非关键自动化。
- 磁盘不足时先停止证据与缓存增长，再阻止会扩大数据的任务。
- 浏览器 Profile 有独立配额和清理策略。
- 用户可按 Task、Provider 或全局终止任务。

全局紧急停止执行：

1. 撤销所有未开始 Action 的授权。
2. 请求取消所有 Brain Turn。
3. 终止 Unterm 子进程树。
4. 停止 Unzoo 正在进行的输入动作。
5. 暂停 Connector 外部写操作。
6. 记录不可篡改的 Emergency Stop 事件。

## 11. 故障恢复

### 11.1 崩溃恢复

每个 Action 在执行前写入意图，执行后写入结果。重启后：

- 未开始：可安全重试。
- 已开始且可查询：先向 Provider 对账。
- 已开始但状态未知：标记 `needs_review`，不得盲目重放。
- 已完成：通过 Idempotency Key 去重。

### 11.2 降级模式

- Brain 不可用：仍可查看历史、Artifact 和诊断。
- Unterm 不可用：禁用本地执行，保留研究与连接器只读能力。
- Unzoo 不可用：禁用浏览器与 Computer Use，允许用户改用 API Connector。
- 数据库只读：停止新任务，允许导出和修复。
- Vault 不可用：所有需要凭据的 Provider 锁定。

### 11.3 Safe Mode

Safe Mode 禁用：

- 自动化触发。
- 外部写操作。
- 桌面输入控制。
- 未签名 Skill 与 Connector。
- 长期 Capability Grant。

用户仍可查看、导出、诊断与执行明确的只读任务。

## 12. 发布质量门槛

### 12.1 Private Alpha

- Windows 安装、升级、回滚和卸载全流程通过。
- 任务与 Artifact 在 Desktop 崩溃后可恢复。
- Codex 与至少一个备选 Brain 通过契约测试。
- Unterm 与 Unzoo 均通过 Capability 协商和降级测试。
- 无已知 Critical/High 权限绕过。
- 诊断包通过秘密扫描。

### 12.2 Public Beta

- macOS 支持完成。
- 自动备份与恢复验证完成。
- 更新分阶段发布和自动停止扩量上线。
- P95 性能目标达到。
- 连续四周崩溃自由会话率 ≥ 99.5%。
- 关键任务成功率 ≥ 90%，且失败能给出可操作的恢复路径。

### 12.3 GA

- 安全响应与撤回机制演练通过。
- 数据导出、删除与保留策略形成用户可验证闭环。
- 连接器和 Skill 供应链审核上线。
- 跨版本迁移覆盖最近两个稳定大版本。
- 支持流程、故障状态页和发布说明常态化。

## 13. 运行手册

每个稳定版本必须维护：

- 已知问题与降级说明。
- 组件兼容矩阵。
- 数据迁移与回滚步骤。
- 紧急停止与 Safe Mode 操作。
- 凭据泄漏处置。
- Connector/Skill 下架与撤销流程。
- Support Bundle 收集和脱敏验证。

任何无法通过 UI 完成的恢复动作，都应被视为待修复的产品缺口，而不是永久依赖用户运行隐藏命令。
