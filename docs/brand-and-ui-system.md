# Unzoo 品牌家族与 Unzoo One UI 系统

> 状态：品牌方向提案 v1
> 范围：Unzoo 母品牌、Unzoo One、Unzoo Browser，以及未来产品的家族扩展
> 核心判断：继承旧标志的意义，不被旧标志的造型与颜色限制。

## 1. 品牌结论

Unzoo 不应被定义成“一个自动化浏览器品牌”，而应被定义为：

> **让智能离开孤立的笼子，在用户控制下观察、思考并行动。**

`Un-zoo` 的品牌张力来自“解除围栏”。它既反对应用孤岛，也反对把 AI 锁在只能聊天的盒子里；但解除围栏不代表解除控制。Unzoo 的价值是把能力释放出来，再用可见边界、明确授权与完整证据交还给用户。

品牌关键词：

- Open：能力开放，系统不封闭。
- Perceptive：能看见环境与上下文。
- Capable：能执行真实工作。
- Sovereign：用户拥有最后控制权。
- Calm：强大但不制造焦虑。

## 2. 现有 Unzoo Browser 标志审计

现有标志由四个强语义组成：

1. U：直接建立 Unzoo 首字母识别。
2. 双手：表达触达、操作与帮助。
3. 中心之眼：表达浏览、感知和 AI。
4. 开放顶部：表达不是封闭容器。

这些语义是有价值的，应当继承。需要优化的是表现方式：

| 现状 | 产品问题 | 新方向 |
| --- | --- | --- |
| 九个以上独立手部形状 | 小尺寸易糊，偏卡通 | 两条开放端点暗示“手”，不描绘手指 |
| 多层径向光晕 | 深浅背景难控制 | 纯几何核心，光晕只作为数字动效 |
| 粉—洋红—紫大面积渐变 | 情绪强，限制产品扩展 | 母品牌单色，产品拥有独立 Signal |
| 眼球具象 | 容易产生监视感 | 抽象“感知核心” |
| Browser 与母品牌共用同一符号 | 产品和公司层级不清 | 同骨架、不同核心语义 |

## 3. 新品牌架构

### 3.1 母品牌：Unzoo

母品牌使用 **Open Vessel / 开放容器**：

- 开放的 U：能力离开围栏，也代表接受外部能力。
- 向上的两个端点：观察与行动，亦可理解为两只抽象的手。
- 中心核心：用户意图和控制权位于系统中央。
- 结构对称：可靠、克制、可预测。

母品牌默认使用纯黑或纯白，不绑定产品色。

### 3.2 Unzoo One

One 在母标核心内加入一条不完全闭合的轨道：

- 中心点是唯一用户意图。
- 轨道是 Brain、Unterm、Unzoo、Connector 和 Skill 的协同。
- 轨道留有开口，表示可扩展、可退出、非封闭生态。
- 外层 U 是安全边界，不是能力边界。

品牌短句候选：

- 中文：**一处发起，万事协同。**
- 英文：**One intent. Every capability.**

产品描述不应使用“万能”“完全自治”等无法建立信任的词。

### 3.3 Unzoo Browser

Browser 保留同一开放 U，核心改为 **Horizon / 视界**：

- 圆形核心表示网页世界与浏览窗口。
- 内部弧线表示视野、页面和地平线。
- 上方点表示正在被理解的焦点，而不是监视用户的眼球。

Browser 品牌短句候选：

- 中文：**让智能真正看见网页。**
- 英文：**The web, visible to intelligence.**

### 3.4 未来产品扩展

任何新产品只允许改变核心内部符号与 Signal 色，不允许重画开放 U：

| 产品 | 核心语义 | 建议 Signal |
| --- | --- | --- |
| Unzoo One | 单一核心与协同轨道 | Ice → Cobalt → Iris |
| Unzoo Browser | 视界与网页焦点 | Teal → Blue |
| Unterm | 光标与可执行会话 | Lime → Emerald |
| Unzoo Cloud | 节点与连续同步 | Sky → Indigo |

## 4. 标志系统

### 4.1 资产

- [`unzoo-master-mark.svg`](../brand/unzoo-master-mark.svg)：母品牌单色标。
- [`unzoo-one-mark.svg`](../brand/unzoo-one-mark.svg)：One 产品标。
- [`unzoo-browser-mark.svg`](../brand/unzoo-browser-mark.svg)：Browser 优化概念标。
- [`unzoo-one-app-icon.svg`](../brand/unzoo-one-app-icon.svg)：One App Icon。

### 4.2 安全空间

以中心核心直径 `x` 为单位：

- 图形标四周最小安全空间：`0.75x`。
- 图形标与文字间距：`0.6x`。
- 与窗口边缘最小距离：`1x`。

### 4.3 最小尺寸

| 场景 | 最小尺寸 | 使用方式 |
| --- | --- | --- |
| 浏览器 Favicon | 16px | 简化为开放 U + 实心核心，移除轨道/视界细节 |
| 系统托盘 | 20px | 单色或双色，不使用光晕 |
| 导航栏 | 24px | 完整产品标 |
| App Icon | 32px | 使用图标底板 |
| 品牌展示 | 64px+ | 可使用完整细节和数字动效 |

需要另外制作 16px 光学校正版；不能直接把 256px SVG 缩小作为最终 Favicon。

### 4.4 禁止用法

- 不旋转开放 U。
- 不把核心替换成人脸或拟人眼球。
- 不给静态 Logo 添加外发光、投影和 3D 斜面。
- 不在一个标志中混用 One 与 Browser 的核心。
- 不把 Signal 渐变铺满大面积背景。
- 不改变开放 U 的比例来适配狭窄空间；应换用横向 Lockup。

## 5. 色彩系统

### 5.1 母品牌中性色

| Token | 色值 | 用途 |
| --- | --- | --- |
| Obsidian 950 | `#080A0F` | 深色主背景 |
| Obsidian 900 | `#0D1017` | 一级表面 |
| Obsidian 850 | `#121620` | 卡片与浮层 |
| Graphite 700 | `#252B38` | 强边框 |
| Silver 500 | `#8D94A4` | 次级文字 |
| Silver 300 | `#B9BFCA` | 辅助信息 |
| Porcelain 100 | `#F7F8FA` | 深色主文字 |
| Porcelain 50 | `#FBFBFC` | 浅色背景 |

暖白不再作为 One 的主底色，避免与冷信号色冲突；需要文档阅读时可使用 Porcelain 页面。

### 5.2 One Signal

| Token | 色值 | 语义 |
| --- | --- | --- |
| Ice | `#63E6FF` | 感知、输入、新信息 |
| Cobalt | `#6C8CFF` | 推理、运行、协调 |
| Iris | `#9B6BFF` | Brain、创造、复杂工作 |

Signal 只出现在：

- 活跃核心。
- 当前执行步骤。
- 主按钮聚焦边缘。
- 选中状态的短线或小面积图标。
- 任务从感知到推理的动效。

Signal 不用于长段文字、整块侧栏、整张卡片背景。

### 5.3 Browser Signal

- Teal：`#24D6B2`
- Web Blue：`#2C9CFF`
- Deep Blue：`#4967FF`

Browser 与 One 通过颜色和核心内部符号区分；底层中性色与排版保持一致。

### 5.4 语义色

- Success `#4CDAA0`：仅表示已验证成功。
- Attention `#F3B85B`：需要用户判断。
- Danger `#FF6B73`：不可逆、高风险或失败。
- Info `#69A7FF`：非风险提示。

品牌 Signal 不能替代语义色。尤其审批不能只用紫色表达风险。

## 6. 字体与排版

### 6.1 字体

产品界面：

```css
font-family: Inter, "SF Pro Display", "Segoe UI", "Noto Sans SC", sans-serif;
```

代码与结构化 ID：

```css
font-family: "SFMono-Regular", "Cascadia Code", "Roboto Mono", monospace;
```

品牌正式发布前应评估定制 `unzoo one` 字标。当前原型不依赖未授权商业字体。

### 6.2 字级

| 角色 | 字号/行高 | 字重 |
| --- | --- | --- |
| Display | 40/48 | 520 |
| Page title | 28/36 | 560 |
| Section title | 18/26 | 560 |
| Body | 14/21 | 420 |
| Label | 12/16 | 520 |
| Micro | 11/15 | 500 |

高级感来自准确比例和留白，不来自把首页标题放大到 72px。

### 6.3 中文规则

- 中文正文最小 13px。
- 中文正文不使用过宽字距。
- 中英文混排数字和单位间使用窄空格。
- 状态、按钮和导航尽量控制在 2–6 个汉字。

## 7. UI 视觉原则

### 7.1 Calm Canvas

背景安静、层级明确。默认页面最多三个纵向层级：

1. Obsidian Canvas。
2. Matte Surface。
3. Floating Surface。

不使用多层透明玻璃叠加。只有浮层、审批和命令面板允许轻度背景模糊。

### 7.2 Intelligence Has a Location

智能状态始终聚焦在 One Core：

- Idle：实心小点，静止。
- Listening：外圈轻微扩张一次。
- Thinking：轨道缓慢运行，不旋转整个 Logo。
- Acting：从核心向当前 Provider 发出短脉冲。
- Waiting：Attention 色固定缺口，停止运动。
- Complete：核心收束为 Success 点。
- Error：不闪烁；核心变为 Danger，并提供文字原因。

用户不需要通过观察虚幻粒子判断 Agent 在做什么，真实状态必须同时有文字。

### 7.3 Evidence Before Spectacle

产品主视觉不是聊天气泡，而是：

- 计划。
- 当前动作。
- 证据。
- Artifact。
- 审批边界。

动效不得遮挡这些内容或拖慢用户审阅。

## 8. 核心组件

### 8.1 Command Composer

- 空状态高度 160–190px，进入任务后收缩到 52px。
- 顶部是自然语言输入。
- 底部左侧是 Mode、工作区和附件。
- 底部右侧是主动作。
- 提交前可展开 Access Preview。
- 聚焦时只显示 1px Signal 环，不大面积发光。

### 8.2 Task Step

每个步骤包含：

- 状态节点。
- 动词开头的标题。
- 一行可验证摘要。
- Provider 标识。
- 耗时和成本，可选。
- Evidence 入口。

进行中步骤使用 Signal 细环；完成步骤只在验证后使用 Success。

### 8.3 Approval Card

审批卡是全产品最需要“严肃感”的组件：

- 标题说明动作，不写模糊的“需要权限”。
- 必须显示对象、目标、范围、不可逆性和请求来源。
- 主按钮使用 Attention 或 Danger，不使用品牌渐变诱导点击。
- 拒绝按钮与批准按钮视觉权重接近。
- 提供“仅本次”“本任务”“长期授权”等独立选择。

### 8.4 Provider Badge

Provider Badge 只表示执行来源：

- Unterm：终端光标图形。
- Unzoo：Browser 产品核心。
- Connector：服务图标。
- Brain：抽象模型节点。

Badge 不使用整块品牌色，避免多个 Provider 同时出现时像彩色标签墙。

### 8.5 Artifact Card

- 视觉缩略图占主要面积。
- 类型、名称、更新时间与验证状态清晰。
- “打开”优先于“下载”。
- 若 Artifact 与外部状态绑定，显示目标系统与最后同步时间。

### 8.6 Evidence Rail

右侧 Rail 不是开发者日志，而是用户可读活动流：

- 默认只显示关键事件。
- 可切换到 Detailed 和 Raw。
- 每个写操作显示 Before / After。
- 当前事件与 Task Step 双向定位。

## 9. 图标与插画

- 使用 1.5px 圆角线性图标。
- 默认 20px，紧凑场景 16px。
- 图标只描述对象或动作，不承担完整状态说明。
- 不使用机器人、章鱼、动物园或拟人助手作为 Mascot。
- 空状态可以使用抽象轨道、开放边界与节点，不使用库存 3D 插画。

## 10. 材质、圆角与阴影

- 小控件：10px。
- 卡片：16px。
- 大 Composer 与主面板：24px。
- Pill 只用于状态、筛选和短标签。
- 边框优先于投影。
- 浮层阴影：`0 24px 80px rgba(0,0,0,.34)`。
- 所有卡片都带阴影会让界面显得廉价，应只给真正悬浮的对象。

## 11. 动效

### 11.1 时间

- Hover / Press：120ms。
- 页面组件进入：220ms。
- Core 编排周期：900–1600ms，按状态变化。
- 状态完成反馈：不超过 600ms。

### 11.2 原则

- 使用位移、透明度和描边变化。
- 不做持续呼吸的大面积背景。
- Waiting Approval 时停止所有“忙碌”动效。
- 遵循 `prefers-reduced-motion`。
- Emergency Stop 立即生效，不等待退出动画。

## 12. 声音

默认关闭。可选声音只有：

- 需要审批。
- 高优先级自动化失败。
- 用户要求任务完成时提醒。

不为普通步骤完成、Token 流式输出或后台浏览播放声音。

## 13. 品牌语言

### 13.1 语气

- 简洁、具体、诚实。
- 用行动和对象说话。
- 不假装人格，不使用讨好式表达。
- 不以“魔法”“无所不能”掩盖风险。

### 13.2 示例

| 不推荐 | 推荐 |
| --- | --- |
| “我需要一些权限来继续” | “允许 Unzoo One 向 1 位联系人发送这份 PDF” |
| “发生未知错误” | “浏览器登录已过期；重新登录后可从第 3 步继续” |
| “AI 正在施展魔法” | “正在比较 12 个来源” |
| “全部搞定！” | “报告已生成；邮件仍等待你的批准” |

## 14. Unzoo Browser 换标建议

### Phase A：共存验证

- 新 Browser 标志只进入 Beta 和内部构建。
- 在 16、20、24、32、48、128、512px 做光学校正。
- 验证任务栏、Profile 图标、安装器、系统通知和网页 Favicon。
- 保留旧标志作为迁移说明的一部分。

### Phase B：产品界面切换

- 更新浏览器壳、设置页、About、安装器和官网。
- Profile 图标按品牌资源 Hash 自动重建。
- 清理历史快捷方式与缓存图标。
- UI 中 Browser Signal 从旧粉紫迁移到 Teal → Blue。

### Phase C：品牌发布

- 母品牌与 One 同期解释新的家族逻辑。
- 发布新旧标志对照和不变的产品承诺。
- 更新商标检索与注册材料。
- 在一个稳定版本周期内保留旧图标识别提示。

## 15. 验收标准

- 母标、One、Browser 在黑白下仍可区分产品核心。
- 16px 简化标可辨认，不依赖发光。
- 关键文字对比度满足 WCAG AA。
- Signal 占单屏可见面积通常低于 8%。
- 所有状态同时有色彩以外的形状或文字表达。
- 审批卡不使用诱导性主品牌渐变。
- 深色、浅色和高对比模式均有明确 Token。
- Windows 100%、125%、150% 缩放不出现半像素模糊。

## 16. 当前交付与后续

当前交付是方向提案，可用于产品原型和内部评审，不应直接作为最终商标注册稿。正式发布前还需要：

1. 为 16–32px 制作独立光学校正版。
2. 将字标转为经过授权与微调的矢量轮廓。
3. 完成浅色、高对比和单色反白资产。
4. 在 Windows 与 macOS 实机验证 App Icon。
5. 进行近似商标检索。
6. 用真实产品界面进行至少一轮可用性测试。

### 16.1 Direction B：Open Gate

在第一版 `One Core` 之后，新增一条以商标显著性优先的探索方向：

- 取消标准 U、具象眼睛与中心目标圆。
- 使用单一圆角能力边界。
- 由数字 `1` 形负空间贯穿边界并通向右上出口。
- 黑白标志先于渐变与 App Icon 成立。

### 16.2 当前选定方向：C1 / Flow One

Direction B 评审后不再继续。当前选定 C1 `Flow One` 进入完整品牌系统阶段：

- 一条连续路径从开放 U 自然上升为数字 1。
- 不使用方形外框、眼睛、中心圆、轨道或负空间切割。
- 黑白主标、Signal 版、Lockup、小尺寸、App Icon、动效和辅助纹样已形成资产家族。
- 完整规范以 [`c1-brand-identity-system.md`](c1-brand-identity-system.md) 为准。
- 完整视觉预览位于 [`brand/c1/brand-system-preview.html`](../brand/c1/brand-system-preview.html)。

C1 在正式对外使用前仍需完成图形与文字商标清查、字标轮廓化和平台图标导出。
